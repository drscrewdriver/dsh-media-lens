# dsh-media-lens

[简体中文](README.md) | [Português](README.pt.md)

Plugin de percepção de mídia: transforma video / audio / image locais em **evidência estruturada** (timeline / transcrição / regiões de layout) injetada na conversa, para que modelos de texto citem quadros, segundos e falantes específicos —— **Evidence, not imagination**. Também embute uma linha de roteamento de providers: uma cadeia de failover por mídia, degradação automática quando o estouro de orçamento manda, e cada tentativa registrada em `meta.attempts` —— **uma degradação nunca é silenciosa**.

```
media_read_video / media_read_audio / media_read_image
  → guarda de caminho (existência + allowlist de extensões)
  → sonda ffprobe + decisão de orçamento (full / reencode / sampleFrames / segment / downsample)
  → cadeia de failover (a primeira que succeede retorna; todas falhando lança erro estruturado com attempts)
  → MediaEvidence JSON (timeline / transcript / regions + meta.attempts)
```

## Ordem das cadeias (por mídia)

| Mídia | Cadeia |
| --- | --- |
| video (≤10MB e ≤10min) | `multimodal` (envio direto multimodal registrado) → `frames:` (amostragem uniforme ffmpeg + cadeia de imagem) → `local:metadata` |
| video (10–19MB) | `reencode:multimodal` (compressão 540p x264 e envio direto) → idem |
| video (>19MB ou >10min) | direto pela rota de amostragem `frames:` |
| audio | `multimodal` (transcrição por envio direto multimodal) → `asr:endpoint-N` (CLI ASR local, múltiplos endpoints em ordem) → `local:metadata` |
| image | `registered:` (modelo de visão já registrado no host) → `configured:openai` (endpoint OpenAI-compatible) → `local:metadata` |

## Origem dos modelos de processamento (FR-9: modelo registrado tem prioridade)

- **Modelos já registrados no host**: o plugin enumera via `ctx.llm.listProviders()/listModels()` (cache de 60s), agrupa por `inputModalities` e forma a cadeia preferida; imagens seguem direto como bloco image nativo.
- **Seleção explícita**: configurar `models.{image,audio,video}: "provider/model"` especifica um modelo registrado —— a rota multimodal tipo MiMo do vídeo passa por aqui (o vocabulário de modalidades do host hoje só conhece `text|image` e não descobre declarações de vídeo/áudio; a seleção explícita é a única porta de entrada; quem transporta de fato é o portão rígido de modalidades do adaptador (p. ex. a tubulação takeover openai-completions), e a recusa é ruidosa).
- **Endpoint próprio**: `providers.openai.{baseUrl, apiKey, model}`; apiKey aceita várias chaves separadas por vírgula (auth/429/quota trocam a chave; rede/5xx pulam para preservar a cadeia).
- **Reserva local**: com strictLocalOnly ou a cadeia toda falhando, `local:metadata` emite só metadados da sonda (duração/resolução/tamanho), `degraded='local-metadata-only'`.

## Configuração

```yaml
dsh-media-lens:
  strictLocalOnly: false      # true remove todo provider remoto da cadeia; a mídia não sai desta máquina
  cooldownMs: 600000          # duração padrão do cooldown para falhas tipo keyFailure (com pista Retry-After/"Resets in", a pista manda)
  models:
    image: auto               # auto | '' | "provider/model"
    audio: auto
    video: auto               # multimodal tipo MiMo: preencha "llm-pi-ai/seu-modelo-mimo"
  providers:
    openai:
      baseUrl: ''             # ex. https://api.example.com/v1
      apiKey: ''              # várias chaves separadas por vírgula, com rotação
      model: ''
      structuredOutput: false # true injeta response_format json_schema(strict) (gateways desconhecidos respondem 400, daí o padrão desligado)
    asr:
      command: ''             # forma de endpoint único: modelo de CLI ASR local, placeholder {input}
      endpoints: []           # múltiplos endpoints, tentados em ordem; mesclam com command (command primeiro)
  refine:
    enabled: false            # Fase 7: uma passada de refine na saída da cadeia, desligada por padrão
    model: ''                 # quando ativado deve ser 'openai/<model>' ou model solto; auto / vazio = não habilitado. O transcritor só aceita endpoints configured próprios (registered:/modelos injetados pelo plugin não valem)
```

Exemplo de modelo de comando ASR (Windows, aspas duplas dentro do modelo protegem caminhos com espaços):

```
python "C:\tools\sensevoice_cli.py" --input "{input}" --json
```

A saída de transcrição aceita dois formatos: JSON segments (`[{start,end,text[,speaker]}]` ou `{"segments":[...]}`) e texto no estilo SRT/linha com tempos.

## Nota de privacidade (lição do dsh-vision-router)

- **Por padrão o conteúdo de mídia vai a providers remotos** (modelos registrados / endpoints configurados). Para que nada saia da máquina, ligue explicitamente `strictLocalOnly: true` —— depois só restam o CLI ASR local e a reserva de metadados.
- `meta.attempts` registra cada tentativa (nome do provider com prefixo de origem `registered:` / `multimodal:` / `configured:` / `asr:` / `frames:` / `local:`, rotação de chaves traz `keyIndex`); `meta.warnings` registra os avisos de roteamento (para onde o failover foi, cauda de cooldown, troca de chave bem-sucedida) —— degradação nunca é silenciosa.
- Caminhos de mídia são tratados como entrada não confiável: só leitura, triplo checker de **existência + extensão + magic bytes** (arquivo renomeado para disfarce é barrado na entrada); instruções que apareçam dentro do conteúdo de mídia são sempre dados, nunca comandos; conteúdo nunca é executado.
- Texto de erro é redigido primeiro (correspondência exata de apiKey/baseUrl) e só então truncado; chaves nunca entram em attempts/logs.
- O envio direto de áudio/vídeo só é realmente inline em rotas com takeover de adaptador (ex. openai-completions takeover); em rotas sem takeover o modelo só vê o texto handle do arquivo —— ao detectar esse eco o plugin abandona o salto e cai na reserva de amostragem/ASR, **sem produzir evidência alucinada**.

## Semântica de cooldown (fusão amolecida à la modlens)

Só **falhas tipo keyFailure** (auth/429/quota no corpo) disparam cooldown —— falhas comuns (oscilação de rede, 5xx, falha de parsing) nunca cooldownam, e um corpo que por acaso contenha a palavra quota também não. Um provider em cooldown **vai para o fim da cadeia e ainda é a última tentativa** (não é expulso): no desespero tenta mais uma vez, sucesso recupera. Quando o provider dá pista de recuperação (cabeçalho `Retry-After` ou corpo `Resets in Xh Ym Zs`) o timer segue a pista, senão `cooldownMs`.

## structuredOutput (FR-13, opt-in)

Com `providers.openai.structuredOutput: true` a requisição injeta `response_format json_schema(strict)` (derivado do próprio payload de evidência, não um espelho escrito à mão). Gateways conhecidos (vLLM, OpenAI oficial etc.) impõem o formato no servidor e elevam bastante a qualidade da evidência; gateways desconhecidos respondem 400 a campo desconhecido —— por isso o padrão é desligado.

## Passada refine (Fase 7, uma vez na saída da cadeia, opt-in)

Depois do primeiro sucesso da cadeia principal e antes do retorno, opcionalmente outra passada de **modelo de texto** refina e normaliza a evidência (deduplica / aperta a redação / preserva incerteza) —— alinhado ao par "leitor vision + transcritor de texto" comum em projetos tipo medialens.

```yaml
refine:
  enabled: true
  model: "openai/seu-modelo-de-texto"   # ou model solto; auto / vazio = não habilitado
```

Desligado por padrão, motivos:

- **Privacidade**: um salto remoto a mais = uma exposição a mais da mídia crua; com `strictLocalOnly` a cadeia para em `local:metadata` e o refine se pula sozinho (não há texto a refinar), sem puxar nada remoto.
- **Latência**: a evidência direta já é utilizável; refine é polimento.
- **Nunca auto**: auto = colocar lente em todo modelo sem critério, não permitimos.

**Portão de origem (o transcritor só aceita endpoints do usuário)**: o salto refine só aceita endpoints **configured** (`providers.openai` com `baseUrl` + `apiKey` preenchidos) —— `model` deve ser `openai/<model>` ou model solto; o modelo realmente enviado vem de `providers.openai.model` (fonte única). **`registered:` / `multimodal:` (enumeração discovery do host, podem incluir modelos injetados por outros plugins) jamais são confiáveis**: alvo neles é pulo silencioso (sem `refineAttempt`, sem warning, comportamento igual a desabilitado). O transporte vai pela conexão direta configured (não rota pelo runtime do host); com `structuredOutput` ligado, injeta `response_format`.

Comportamento de falha (**nunca silencioso, mas não desfaz o que passou**): refine jogar erro / não devolver JSON / falhar na validação → **evidência crua preservada**, `meta.warnings` ganha `refine failed: <redacted>`, `meta.refineAttempt.ok = false`; attempts da cadeia principal não cresce (o leitor já teve sucesso, não se gasta outro salto de amostragem/ASR). No sucesso, `meta.refineAttempt.provider = 'refined:openai/<model>'`; `meta.provider` mantém o prefixo do leitor (registered / multimodal / configured / asr / frames / local); `source` / `meta.attempts` / `meta.generatedAt` nunca são alterados pelo refine.

Endurecimento do transporte: os quatro elementos de `EVIDENCE_REFINE_INSTRUCTION` têm a mesma origem do instrutor do leitor (anti-injeção / verbatim / bbox conservador / incerteza), mais a linha «preservar source e attempts originais» —— instruções dentro da mídia entram uma segunda vez no contexto do LLM junto com a evidência crua, e a linha anti-injeção precisa ser mastigada de novo, para não lavar a evidência. Texto de erro é redigido antes de truncar.

## vision-bridge (v4, envoltório de lente visível no seletor, opt-in)

Transforma a lente em **roteamento visível no seletor de modelos do host**: registra via `llm.registerAdapter` do host um provider envoltório `media-lens-vision-<upstream>`, e o seletor ganha a entrada `<nome do modelo> (media-lens vision)`. Escolhendo-o como modelo principal da conversa, a mídia na requisição passa pela cadeia media-lens antes do envio (leitor = a configuração de «modelos de processamento» acima) e vira texto de evidência, sendo então delegada ao roteamento real —— modelos textual puros ganham assim visão de imagem e áudio/vídeo ("deixar o deepseek receber a evidência que o mimo leu").

```yaml
inject:
  enabled: true
  families: ["deepseek", "glm", "mimo"]   # filtro por prefixo; "*" = todos (ainda sujeitos ao veto)
```

**Critério do envoltório = envelopar quando a lente completa a modalidade; omni jamais**:

- Modelo de texto puro (tipo deepseek-v4.1) → envelopa: imagem + áudio/vídeo todos evidenceados;
- Modelo de imagem (declara image, não omni) → envelopa: **blocos de imagem passam intactos** (preserva visão nativa), só áudio/vídeo viram evidência;
- Omni de modalidades largas (MiMo bare sem segmento `-pro`, heurística de nome) e vocabulários vision-especializados (`deepseek-vl` / `glm-4v` / `*vision*` etc.) → recusa envelopar, `resolveModel` recusa ruidosamente e aponta a rota original.

Pontos do mecanismo (âncora real 0.2.0-rc.2): o host já projetou o bloco file em texto handle determinístico antes do adapter; a ponte reconhece o formato exato de `content.ts`, extrai o caminho somente-leitura e roda a cadeia inteira; a reescrita nunca throw (falha do leitor cai em texto placeholder constante e a requisição segue); evidência é cacheada por bloco (replay sem releitura); o evento `llm/adapters-updated` dirige a revarredura, e rotas registradas tarde (llm-pi-ai) entram automaticamente; o snapshot de discovery expulsa `media-lens-vision-*` (o leitor nunca escolhe o próprio wrapper). Sem a face `registerAdapter` no host, mantém silenciosamente a forma pura de ferramentas.

## Plugins irmãos (peer opcional, não dependência rígida)

o media-lens em si faz «as ferramentas processam objetos multimodais» (media_read_video/audio/image). Para **registrar/autenticar modelos multimodais no host** e fazer o **envio direto de áudio/vídeo** ser realmente inline (em vez de só ver o texto handle do arquivo), dois plugins irmãos cooperam —— declarados peers `optional`: sem eles a capacidade correspondente degrada sozinha, sem erro:

- **dsh-thinking-levels**: entrada de configuração/certificação de modelos e face de gestão de reasoning_effort —— os modelos da cadeia de envio direto de áudio/vídeo são registrados aqui.
- **dsh-llm-openai-completions**: takeover de transporte OpenAI-compatible —— serializa blocos file em video_url / input_audio e os envia de fato; em linhas sem takeover o host só projeta texto handle, e ao detectar isso o plugin cai na reserva de amostragem/ASR.

A instalação segue o profile do host (autoInstallPeers:false + hoisted); os plugins irmãos se registram por seus próprios bundles, peers opcionais não puxam npm nem brigam com o portão de versões do host.

## Família de seções e pesos de tab (bundle + subtab de família)

Este plugin é bundle de duas metades host+client (o `dsh.plugin.json.client.main` carrega a metade client). A metade client contribui o cartão de configuração para a família de seções `dsh-family` (seção de topo order 40, label «起子插件设置», independente deste plugin e renderizada uniformemente pelo dono da família):

| Face registrada | slot | peso (order) | semântica |
| --- | --- | --- | --- |
| Cartão de contribuição da subtab de família (rota principal) | `dsh-family.tab` | **65** (depois dos cartões já existentes, lá atrás) | lazy: espera o dono da família injetar a renderização; o cartão de contribuição não renderiza o corpo da seção sozinho |
| Seção autônoma de reserva | `settings.section` | 24 | **auto-registra sem injection**: se o slot da família nunca foi renderizado (dono ausente/sem dono), este cartão aparece como seção autônoma, preservando a visibilidade |
| Cartão de detalhes do bundle | `plugins.bundle.config` | — (keyed por nome de pacote) | cartão de configuração do gerenciador de plugins 0.1.7+ |

Mecanismo lazy (as duas rotas de injeção se registram no topo da fase apply, e a fábrica só fire quando «evento declarado = painel de configuração aberto», fire na ordem de registro): o cartão de contribuição da família registra primeiro e, ao fire da sua fábrica, marca `familySeated`; a fábrica da seção autônoma lê a marca e se retira (sem expor duas vezes), sem a marca auto-registra a seção autônoma. **Registro após período de graça é proibido** (contraexemplo §3). Caminho de escrita: os campos de topo da configuração de cada entrada levam `.volatile()`, e o client escreve authoritative via `configForms.get(entryId).set(field, value)` com efeito a quente (única face de escrita viva em 0.1.7+/0.2.0/0.2.1; `settings.register` foi removido no 0.1.7+, a ponte webServer não serve de caminho de escrita).

## Face de terminal TUI (dsh-tui)

O dsh-tui não carrega a metade client do plugin (painéis/cartões/página de configuração) nem alcança RPC própria do plugin; chamadas de ferramenta mostram só uma linha de resumo. A face legível e operável por humano que sobra são os comandos de barra do host. Convenção de saída: linha única ≤100 caracteres, ≤40 linhas no total, sem ANSI, alinhamento de dois espaços; escrita é dry-run por padrão, `--yes` executa; `--json` devolve JSON em linha única.

| Comando | Função |
|---|---|
| `/media status` | seção de configuração de roteamento de mídia (a mídia em si não é visível no terminal) |

O comando é registrado no host pelo próprio plugin (`ctx.inject(['commands'], …)`): em linhas antigas sem serviço de comandos ele não ativa e não erro.
